# Personal delegate agents ("digital twin of a person") — how products and research define, create and govern them, 2025–2026

Scope note: research run 2026-10-12. Findings are grouped under the five key questions. Where only a search snippet or a secondary source was available, that is said. Nothing below is invented; where a product's internals could not be confirmed from a primary page, it is listed under Gaps.

A plain-English reading for the founder, before the detail: nobody sells a "twin" that holds a person's authority inside a work system and approves things for them. What exists in 2025–2026 is (a) **identity vendors** giving an agent its own account with a named human "sponsor" or "owner" and a way to act *for* a user with a token that records both names; (b) **executive "clone" products** (Delphi, Tavus) that copy a person's *voice and knowledge* for conversation, not their *authority*; (c) **personal-assistant agents** (Lindy, OpenAI's ChatGPT agent, Claude Code, Microsoft Copilot) that ask before anything consequential; and (d) **research and draft standards** that say how to write down what an agent may do, for how long, and up to what amount. The accountability rule in every source is the same: the human stays responsible for what is done in their name.

## Key question 1 — Which products or prototypes let a user create a personal agent that acts with their authority, and what do they call it?

### Takeaway
The identity layer calls it an **agent identity** with a human **sponsor** (Microsoft), an agent registered to a human **owner** (Okta), or an agent with a cryptographic identity that acts **as itself or for an end user** (Google). The consumer/executive layer calls it a **digital mind** or **clone** (Delphi), an **avatar** (Otter's CEO), a **digital twin** (Zoom's CEO), or an **AI employee / teammate** (Lindy). Research calls it a **Manager Clone Agent** (CMU/Emory, CHI 2026) or a **custodial user agent** (US draft bill). None of the products found lets a user hand a twin real approval authority inside an enterprise record without a human confirmation step; the clones are for presence and knowledge, the identity constructs are for IT.

### Cited Findings
- **Microsoft Entra Agent ID.** "An agent identity is a special service principal in Microsoft Entra ID… It doesn't have credentials on its own." Agents are created from a reusable **blueprint**; "Agent identities can have a **sponsor**, which records the human user or group that's accountable for an agent… used for various purposes, such as contacting a human in case a security incident happens." An agent can also be given an optional **"agent's user account"** — "a user account in the Microsoft Entra tenant that is decorated as an AI agent" with a strict 1:1 link to the agent identity — for systems that require a user account. Doc dated 2026-03-30, updated 2026-06-15. — [Microsoft Learn: Overview of agent identities](https://learn.microsoft.com/entra/agent-id/agent-identities)
- Entra Agent ID was first introduced May 2025 and announced in public preview at Ignite (Nov 2025); Microsoft's December 2025 Entra blog said all discussed capabilities were in public preview. — [Microsoft Learn: What's new, Ignite 2025](https://learn.microsoft.com/en-us/entra/fundamentals/whats-new-ignite-2025); [Compass Security analysis, June 2026](https://blog.compass-security.com/2026/06/entra-agent-id-from-a-security-perspective/)
- **Microsoft Agent 365** (Ignite, Nov 2025) is described as a "control plane for managing, securing, and observing agents across the enterprise," in early access via the M365 admin center under the Frontier Program. — [Microsoft news, Ignite 2025](https://news.microsoft.com/en-hk/2025/11/19/microsoft-ignite-2025-empowering-the-frontier-firm-with-ai-agents-and-copilot/); [Directions on Microsoft, Nov 12 2025](https://www.directionsonmicrosoft.com/?p=163623)
- **Okta for AI Agents** (press release 25 Sept 2025): Universal Directory "registers agent identities," "attributing risk classification and ownership to every non-human identity"; Okta Identity Governance handles governance and audit; Identity Threat Protection monitors sessions. Availability: "Phase 1 in EA, FY27 Q1 and Phase 2 in GA, FY27." **Cross App Access (XAA)**, "a new open protocol," "shifts control from individual applications to the identity layer"; by "pre-approving agent-to-app or app-to-app connections, XAA reduces the number of consent prompts"; "Unauthorized requests can be audited or blocked" and admins can "immediately revoke access in case of an incident." Named supporters include Salesforce, Glean, AWS, Google Cloud. — [Okta press release via Placera, 2025-09-25](https://www.placera.se/pressmeddelanden/okta-a-new-okta-innovations-secure-the-ai-driven-enterprise-and-combat-fraud-with-an-identity-security-fabric-20250925); [heise](https://heise.de/-10696395)
- **Auth0 for AI Agents** features listed by a third-party tracker: user login for agents, Token Vault for third-party API tokens, asynchronous approval over CIBA, fine-grained authorization for RAG, authorization for MCP servers; GA date given as 2025-11-19 (not confirmed from an Okta/Auth0 primary page). — [guptadeepak.com changelog](https://guptadeepak.com/ciam-compass/changelog/auth0-for-ai-agents-ga/)
- **Google Cloud Agent Identity.** "Agent Identity provides a strongly attested, cryptographic identity for each agent that is based on the SPIFFE standard." Agents "can securely authenticate to MCP servers, cloud resources, endpoints, and other agents" — "either as itself or for an end user." Unlike service accounts, agent identities "are not shared by multiple workloads by default, can't be impersonated, and don't allow… long-lived service account keys." For user-delegated access, an "auth manager" vault holds the user's OAuth credential so "the agent can never access the raw credential." Works with Agent Registry and Agent Gateway; Gemini Enterprise is a listed consumer. — [Google Cloud IAM: Agent identity overview](https://docs.cloud.google.com/iam/docs/agent-identity-overview); [Auth as agent's own identity](https://docs.cloud.google.com/iam/docs/auth-agent-own-identity)
- **Salesforce Agentforce.** Salesforce's page says the Audit Trail "provides the data you need to track AI agent actions and outputs." Third parties disagree on identity: Obsidian says an agent "acts under its own assigned user identity, so that user's permission set defines its reach rather than the invoking employee's permissions"; another blog says it inherits the running user's access. Obsidian also notes standard logs record "what the agent did, not what it was authorized to do or on whose behalf." — [Salesforce: How Agentforce works](https://www.salesforce.com/agentforce/how-it-works/?bc=DB); [Obsidian Security](https://www.obsidiansecurity.com/academy/securing-salesforce-agentforce); [Trailhead: Agentforce guardrails](https://trailhead.salesforce.com/content/learn/modules/trusted-agentic-ai/explore-agentforce-guardrails-and-trust-patterns)
- **OpenAI ChatGPT agent** (July 2025) "request[s] confirmation before taking 'actions of consequence' such as sending an email"; has a **takeover mode** where the user steps in to type or log in; OpenAI's help center lists "user confirmations for high-impact actions," refusal patterns, prompt-injection monitoring, and a "watch mode" requiring supervision on certain sites, and says these "don't eliminate all risks." — [OpenAI help: Agent](https://help.openai.com/en/articles/11752874-agent); [SD Times](https://sdtimes.com/ai/chatgpt-now-has-an-agent-mode/); [Decrypt](https://decrypt.co/330714/openais-chatgpt-agent-launches-expanded-powers-elevated-risk)
- **Anthropic Claude Code.** Default behavior "asks for approval before running commands or modifying files," which "creates a lot of clicking, which leads to approval fatigue"; a sandbox and a `--dangerously-skip-permissions` flag exist, the latter "unsafe in most situations"; a research-preview **auto mode** routes permission requests through a classifier that allows safe actions and blocks risky ones like file deletion. — [Anthropic engineering: Claude Code auto mode](https://anthropic.com/engineering/claude-code-auto-mode); [TechRadar](https://techradar.com/pro/anthropic-gives-claude-code-new-auto-mode-which-lets-it-choose-its-own-permissions)
- **Lindy** positions itself as an "AI employee"/teammate for individuals; its "Human in the Loop" feature "escalates edge cases to you for approval before the agent takes action"; a "Confirm before sending" setting lets the agent draft and ask via Slack or web before any external action, moving trusted skills to fully automated later; one review describes a second-model **Validator** that reads a proposed side-effecting action, its justification and history and "approves or blocks it," catching an attempted delete when the user asked for an archive. Zapier's own comparison lists Lindy as having persistent memory and "ambient/proactive behavior." — [Cerebral Valley: Lindy](https://cerebralvalley.beehiiv.com/p/lindy-building-first-ai-employee); [Dupple review, Jul 2026](https://dupple.com/reviews/lindy); [Zapier vs Lindy](https://zapier.com/compare/zapier-vs-lindy)
- **Executive clones.** Axios (10 June 2025): execs use Delphi and Tavus to upload "writings, keynote speeches, interviews and even their meetings" to create text/voice chatbots and video avatars; Otter CEO Sam Liang floated a "Sam Bot" to attend meetings, which he prefers to call his avatar. — [Axios, 2025-06-10](https://www.axios.com/2025/06/10/ai-ceo-clones-trust-gap) (page returned 403 on fetch; details from search summary)
- **Delphi** builds "digital minds" from the person's own content — "as few as four documents, scaling up to thousands, including emails, chat transcripts, YouTube videos, podcasts, or voicemails"; a "strictness score" controls how the clone replies; Video Clones with Tavus; deployable to a website, Slack or a phone number. — [AssemblyAI customer story](https://www.assemblyai.com/customers/delphi-customer-story); [VentureBeat (2023 launch)](https://venturebeat.com/ai/you-can-now-make-an-ai-clone-of-yourself-or-anyone-else-living-or-dead-with-delphi); [aiindigo review, 2026](https://aiindigo.com/blog/scaling-your-persona-a-thorough-review-of-delphi-in-2026)
- **Zoom** CEO Eric Yuan described "digital-twin technology" to send AI versions of oneself to meetings, acknowledging "AI is not there yet" (2024 piece). — [NY Sun](https://nysun.com/article/zoom-ceo-hopes-to-create-digital-ai-clones-that-will-attend-meetings-for-you)
- **Research prototype / concept:** "Manager Clone Agents" — "An AI system trained on a manager's work communications and decision patterns," which at higher autonomy "acts as a functional delegate that perceives context, reasons through tasks, and executes actions with little or no intervention." Hu, Xiao, Shen (CMU HCII) and Cao (Emory); CHI 2026, arXiv v3 29 Jan 2026. — [arXiv 2509.10993](https://arxiv.org/html/2509.10993v3)
- **US draft law** term: "custodial user agents" — "software expressly authorized by a user to interact with a large online platform provider on that user's behalf" (Warner discussion draft, 29 June 2026). — [DWT, July 2026](https://www.dwt.com/blogs/artificial-intelligence-law-advisor/2026/07/ai-agent-act-consumer-ai-regulation); [CIO.com](https://www.cio.com/article/4191009/how-the-senates-ai-agent-act-could-reshape-enterprise-ai-governance.html)

### Inferences
- The market has split the "twin" into two things that are never sold together: the *likeness* (Delphi/Tavus — voice, style, knowledge, for talking to others) and the *account* (Entra/Okta/Google — an identity with a human sponsor, for calling systems). A work-system twin that approves hours or bills is the account kind with a likeness optional, and nobody found here ships that combination.
- The word that survives across vendors for the human behind the agent is **sponsor** or **owner**. "Acting as" the person is modeled as acting *for* the person with both names on the token, not as logging in as them.

### Gaps
- No primary Microsoft page for Agent 365's permission model or for how a Copilot personal agent inherits a user's rights was found; only release notes and press coverage.
- Auth0 for AI Agents GA date and Token Vault/CIBA details could not be confirmed from an Okta/Auth0 primary page.
- Salesforce's official statement of whether an Agentforce agent runs as its own user or the invoking user was not found; third parties conflict.
- No product doc found for Relay, Zapier Agents, or any "AI twin" startup offering delegated *approval* authority inside an HR/finance system.

## Key question 2 — How is delegated authority expressed (scopes, on-behalf-of tokens, inheritance, spend caps, approval rules), and what do identity vendors say?

### Takeaway
The working pattern in 2025–2026 is **OAuth with two names in one token**: the user as subject, the agent as actor, both shown on the consent screen and both logged. Spend caps, time limits and task-bound revocation are recognized as needs that plain scopes cannot express, and are being drafted (IETF drafts, EU eIDAS 2 attestations), not yet standardized.

### Cited Findings
- **Entra token shapes.** Agent identities can "Request user tokens from Microsoft Entra ID for an authenticated user. The subject of the token is a user, while the actor is the agent identity." "Autonomous agents acquire app tokens on behalf of the agent identity. Interactive agents called with a user token acquire user tokens on behalf of the agent identity," provided "the user or tenant admin consented for the agent identity to the corresponding scopes." Blueprints let an admin "Apply a conditional access policy to all Sales Assistant Agents… Disable all… Revoke a permission grant for all." Agent identities are single-tenant. — [Microsoft Learn: agent identities](https://learn.microsoft.com/entra/agent-id/agent-identities)
- **Google's model.** Permissions are granted to the agent as principal via IAM allow/deny policies; Google suggests "grant common permissions such as quota, logging, or access to models to all agents in the project… Then grant specific narrow permissions to individual agents for more sensitive permissions such as access to data." Delegated end-user credentials are "encrypted by the auth manager and decrypted at the gateway." — [Google Cloud: Agent identity overview](https://docs.cloud.google.com/iam/docs/agent-identity-overview)
- **Okta.** XAA pre-approves agent-to-app connections at the identity layer; Universal Directory assigns risk class and owner. — [Okta press release, 2025-09-25](https://www.placera.se/pressmeddelanden/okta-a-new-okta-innovations-secure-the-ai-driven-enterprise-and-combat-fraud-with-an-identity-security-fabric-20250925)
- **IETF on-behalf-of draft** (`draft-oauth-ai-agents-on-behalf-of-user`, rev -02, Aug 2025, not yet adopted by the OAuth WG): adds `requested_actor` to the authorization request (the agent's ID, shown on the consent screen) and `actor_token` to the token request; the issued JWT carries `sub` = the user, `azp` = the client, `act.sub` = the agent, so "a resource server can log all three" and "an auditor [can] query what a specific agent did for a specific user." The consent screen "names the client, the agent, and the requested scopes… a generic 'this app wants to read your email' prompt is not enough." Limits: single hop only; actor-token bootstrapping out of scope; revoking the agent without revoking the user "is not detailed." — [WorkOS, 28 Apr 2026](https://workos.com/blog/oauth-on-behalf-of-ai-agents)
- **Practitioner rule:** when an agent must act for a specific user, use OAuth 2.0 token exchange "instead of reusing the user's session"; machine-to-machine calls use client credentials. — [guptadeepak.com: delegated auth](https://guptadeepak.com/agent-security/delegated-auth/)
- **ICML 2025 position paper, "AI Agents Need Authenticated Delegation."** Third parties must verify "(a) the interacting entity is an AI agent, (b) that the AI agent is acting on behalf of a specific human user, and (c) that the AI agent has been granted the necessary permissions." Proposes three tokens on top of OIDC/OAuth: a user ID token, an **agent-ID token** (capabilities and limitations), and a **delegation token** "signed by the human, referencing the user and agent tokens, and specifying the agent's scope," which "should specify validity conditions, such as expiration time or revocation endpoints" and may carry audit URLs. Suggests UMA so a user sets policy once for many agents; W3C Verifiable Credentials as an alternative. — [ICML 2025 paper text](https://object.cloud.sdsc.edu/v1/AUTH_da4962d3368042ac8337e2dfdd3e7bf3/ml-papers-txt/ICML/2025/position_ai_agents_need_authenticated_delegation__0372fdcc.txt)
- **IETF use-cases draft** (`draft-chen-oauth-agent-authz-use-cases-02`, 12 Aug 2026, China Mobile/CNNIC/Huawei): UC1 "Personal Digital Assistant" needs "Pre-Authorized Constraints" ("structured constraints previously approved by the user" checked at execution time), "Task-Scoped Revocation" ("revoke authority associated with a specific task"), and "Action-Specific Approval" ("the approval should be bound to the concrete action parameters"); UC3 "Agent as Full Proxy" needs "Delegated Authority with Constraints" — "a constrained subset of the user's full permissions" — and notes "scope cannot express limits such as rate caps"; UC6 needs a "Verifiable Delegation Chain" and "Principle of Least Privilege at Each Step"; UC11 needs "Non-Repudiable Execution Evidence." Security section asks for "a durable record of the authorization grant event itself" and warns "AI agents can click 'Approve' buttons themselves." — [IETF datatracker](https://datatracker.ietf.org/doc/html/draft-chen-oauth-agent-authz-use-cases-02)
- **DAAP draft** (`draft-mishra-oauth-agent-grants-01`, March 2026) proposes "budget controls for spending limits" and "a multi-agent delegation model with cascade revocation," claiming to fill "a gap unaddressed by existing OAuth 2.0 extensions." (Mirror returned 404 on fetch; from search summary.) — [Internet-Draft mirror](https://ftp.kaist.ac.kr/ietf/draft-mishra-oauth-agent-grants-01.html)
- **OAuth AI Scopes draft** (Dec 2024, expired June 2025) proposed token constraints "including spend limits and model restrictions" — for model-API access, not agent actions. — [IETF draft](https://www.ietf.org/ietf-ftp/internet-drafts/draft-hemanth-oauth-ai-scopes-00.html)
- **EU:** under eIDAS 2, the EU digital identity wallet can carry attestations stating "an agent's limits, such as spending caps, duration, and permitted actions, giving merchants verifiable proof of authority." — [Tech Policy Press, 12 Dec 2025](https://techpolicy.press/when-an-ai-agent-says-i-agree-whos-consenting)
- **NIST NCCoE** published a concept paper (Feb 2026) "proposing to adapt identity and authorization frameworks, including OAuth 2.0 extensions, for non-human AI agents"; comments due 2 April 2026. — [CSA research note, Apr 2026](https://labs.cloudsecurityalliance.org/research/csa-research-note-nist-ai-agent-standards-initiative-complia/)

### Inferences
- For Etyme's purposes, "delegation" has a concrete shape across all of these: **a record signed by the person, naming the agent, listing what it may do, up to what amount, until when, and where to revoke it** — and every action carries both the person's and the agent's name. That is what a `delegation` row would hold.
- A spend cap or approval threshold is *not* something OAuth scopes carry today; it must live in the application (the system of record) and be checked at execution time, which the use-cases draft explicitly calls out.

### Gaps
- No vendor was found that ships a per-user **spend cap** or **time-boxed power** on an agent as a first-class product feature; all are drafts or recommendations.
- Multi-hop delegation (person → agent → sub-agent) is only informational in current drafts.

## Key question 3 — How do users teach the twin without a big UI, and what is the evidence on what works?

### Takeaway
Products teach by **ingesting the person's own material** (Delphi), by **memory built from interactions with review/edit/delete** (Microsoft Work IQ), and by **correcting the agent after it acts** (Lindy, PAHF research). The strongest evidence is that **showing beats telling**: agents given a person's past choices predicted them better than agents given the person's stated preferences, and models are bad at picking up implicit corrections.

### Cited Findings
- **Delphi**: trained on existing content — videos, documents, podcasts, writing — "as few as four documents"; most uploads are audio/video and are transcribed first; a "strictness score" controls replies. — [AssemblyAI customer story](https://www.assemblyai.com/customers/delphi-customer-story); [aiindigo review](https://aiindigo.com/blog/scaling-your-persona-a-thorough-review-of-delphi-in-2026)
- **Microsoft Work IQ** (Ignite 2025): "the intelligence layer that enables Microsoft 365 Copilot to know you, your job, and your company inside and out." Coverage: it "builds memory based on your interactions, so Copilot can remember things like your preferences or recent conversations"; conversational memory combines "explicit signals, such as work profile, custom instructions, and saved preferences, with insights from previous chats"; "conversational memories can be reviewed, updated, or deleted at any time" (Frontier program). — [Microsoft 365 blog](https://www.microsoft.com/en-us/microsoft-365/blog/?p=280039); [Advania](https://community.advania.co.uk/discussion/431/whats-new-in-microsoft-365-december-2025); [Redmondmag, 18 Nov 2025](https://redmondmag.com/articles/2025/11/18/microsoft-expands-copilot-role-in-office.aspx)
- **Lindy**: corrections improve the assistant; a tutorial suggests correcting "5–10 significant misclassifications per week"; "Confirm before sending" first, then move trusted skills to fully automated. — [aiindigo Lindy tutorial](https://aiindigo.com/tutorials/getting-started-with-lindy-automate-inbox-triage-and-meeting-scheduling); [automationatlas](https://automationatlas.io/answers/how-to-build-a-lindy-ai-assistant-2026/)
- **PAHF (Meta/Princeton, Feb 2026)**: an agent that "asks clarifying questions before acting, retrieves stored per-user preferences, and updates its memory after user corrections"; "explicit memory plus both feedback channels outperforms no-memory and single-channel baselines, and… adapting to preference drift depends on post-action correction." — [arXiv 2602.16173](https://www.arxiv.org/pdf/2602.16173)
- **Ellis & Huang, "Should I State or Should I Show?" (arXiv 2603.29317, 2026)**: in an online lottery-choice experiment, "an AI agent given revealed-preference data (past choices) predicted people's decisions more accurately than one given stated-preference prompts," traced to "people struggling to write down their own preferences." (Body text not readable from PDF fetch; from search summary.) — [arXiv 2603.29317](https://arxiv.org/pdf/2603.29317)
- **"Why Personalized LLM Agents Fail at Implicit Preference Updates" (NeurIPS 2026 listing)**: models "often fail to update decisions after implicit user signals, even when humans resolve those same updates at high accuracy"; the failure depends on how much weight the model gives the user's initial statement. — [NeurIPS 2026](https://neurips.cc/virtual/2026/173328)
- **ICML 2025 delegation paper** on plain-language rules: "users state permissions in plain language, an LLM converts them into formal policies… and the user reviews and approves them before enforcement"; "The brittleness of natural language mechanisms makes them unsuitable for production-level usage of AI agents"; "Structured resource scoping reduces the reliance on model alignment alone." — [ICML 2025 paper](https://object.cloud.sdsc.edu/v1/AUTH_da4962d3368042ac8337e2dfdd3e7bf3/ml-papers-txt/ICML/2025/position_ai_agents_need_authenticated_delegation__0372fdcc.txt)
- **CMU Manager Clone study**: managers imagined "pre-uploaded talking points" (M17) and "pre-approved decision bands" (M16); M5 joked a clone keeping "a memory of everything I've said" could reflect the manager back at them; workers "wanted access to training data and to know what data is collected about them" (W3). — [arXiv 2509.10993](https://arxiv.org/html/2509.10993v3)

### Inferences
- The onboarding with the least interface that the evidence supports is: **watch the person's past decisions in the record** (approvals, rejections, reasons), **ask one question before the first act of each kind**, and **learn from the correction after**. Asking the person to write their rules up front is the weakest channel, because people cannot state their own preferences well.
- Plain-language rules are fine as the *input*, but must be turned into a structured, reviewable rule before they are enforced — the paper's "LLM translates, human approves" step.

### Gaps
- No controlled study was found comparing onboarding channels (conversation vs examples vs imported rules) for a *work-system* delegate; the evidence is from lab choice tasks and inbox tools.
- Microsoft's own documentation of what Work IQ memory stores and how it is reviewed was not retrieved; details are from press coverage.

## Key question 4 — What governance and accountability patterns are recommended (audit attributed to the human, reversible-by-default, never silently permit, separation of duties)?

### Takeaway
Every source converges on: **the human sponsor owns the decision**, **every action is logged with both the human and the agent named and with the reason**, **consequential actions get a human confirmation bound to the exact parameters**, and **the agent that proposes must not be the identity that approves**. "Reversible-by-default" appears as a product pattern (Replit's one-click restore, planning-only mode) rather than a stated standard.

### Cited Findings
- **Accountability to the sponsor.** Entra's sponsor "records the human user or group that's accountable for an agent." — [Microsoft Learn](https://learn.microsoft.com/entra/agent-id/agent-identities). Okta attributes "ownership to every non-human identity." — [Okta press release](https://www.placera.se/pressmeddelanden/okta-a-new-okta-innovations-secure-the-ai-driven-enterprise-and-combat-fraud-with-an-identity-security-fabric-20250925)
- **CMU/Emory recommendations (CHI 2026):** "Managers should keep responsibility for decisions made in their name"; organizations should prohibit using clone agents "as shields for deflecting blame"; "Audit trails should preserve the line between human intent and agent action"; show when an agent is mediating ("labeled message headers," distinctive avatars, interaction summaries); manager-designated **human-only zones** (onboarding, conflict, performance feedback) enforced by the interface; "quick escalation to the human manager… and pausing the agent when relational trust is at risk"; "binding worker preferences that bar agent participation in contexts like evaluation or promotion"; worker access to interaction histories to contest errors; appeal channels not dependent on managerial discretion. W15: "Decisions involving firing, recruiting, or promoting must be reviewed by a human." Tiered autonomy across **representation, proactivity, delegation**, tuned together. — [arXiv 2509.10993](https://arxiv.org/html/2509.10993v3)
- **Audit must name three parties.** The on-behalf-of token lets a resource server log user, client and agent, so an auditor can ask "what a specific agent did for a specific user." — [WorkOS](https://workos.com/blog/oauth-on-behalf-of-ai-agents). Salesforce commentary: standard logs "record what the agent did, not what it was authorized to do or on whose behalf"; a dedicated agent user is recommended so its writes are distinguishable from integration writes. — [Obsidian Security](https://www.obsidiansecurity.com/academy/securing-salesforce-agentforce); [Decryption Digest](https://www.decryptiondigest.com/blog/salesforce-agentforce-permission-debt-data-exposure-audit)
- **Intent as well as execution.** A defensible trail needs "execution observability (what the agent did) and intent observability (why it did it)"; most programs capture only the first. — [NHI Mgmt Group](https://nhimg.org/articles/ai-agent-audit-trails-are-shifting-from-access-to-behaviour/)
- **Approval bound to parameters; grant recorded; agent cannot self-approve.** IETF use-cases draft: "Action-Specific Approval… bound to the concrete action parameters"; "a durable record of the authorization grant event itself"; "Non-Repudiable Execution Evidence"; warning that "AI agents can click 'Approve' buttons themselves" (Agent-Operable Consent Surfaces). — [IETF draft](https://datatracker.ietf.org/doc/html/draft-chen-oauth-agent-authz-use-cases-02)
- **Separation of duties for agents** (vendor sources only): SoD "separates critical functions so that no single identity can both request and approve a high-risk action"; "the agent that proposes should not be the same identity that finalizes high-risk actions"; human approval "only means something if the system can tell the initiating person apart from the agent acting," and the approval record should keep the full delegation chain. — [Gravitee](https://gravitee.io/corpus/gen-1152/enterprise-control/segregation-of-duties-and-approval-workflows-for-enterprise-ai-agent-and-api-control-planes.html); [CloudEagle](https://www.cloudeagle.ai/blogs/segregation-of-duties-ai-agents); [hoop.dev](https://hoop.dev/blog/segregation-of-duties-for-agentic-ai-a-practical-guide/)
- **Enforcement independent of the model.** "Structured resource scoping reduces the reliance on model alignment alone," so a tricked model is still limited by permissions. — [ICML 2025 paper](https://object.cloud.sdsc.edu/v1/AUTH_da4962d3368042ac8337e2dfdd3e7bf3/ml-papers-txt/ICML/2025/position_ai_agents_need_authenticated_delegation__0372fdcc.txt)
- **Human confirmation before consequence** is the shipped default at OpenAI (confirmation for "actions of consequence," watch mode) and Anthropic (ask before commands/edits; classifier-gated auto mode in preview), and at Lindy (Human in the Loop, Validator). — [OpenAI help](https://help.openai.com/en/articles/11752874-agent); [Anthropic engineering](https://anthropic.com/engineering/claude-code-auto-mode); [Dupple on Lindy](https://dupple.com/reviews/lindy)
- **Reversibility as a product response.** After the Replit incident the company "announced changes such as separating development and production databases and adding a planning-only mode," and backups enabled a "one-click restore." — [eWeek, 22 Jul 2025](https://www.eweek.com/news/replit-ai-coding-assistant-failure/); [Storyboard18, 23 Jul 2025](https://www.storyboard18.com/amp/digital/replit-ceo-apologises-after-ai-tool-deletes-company-data-fakes-4000-profiles-76185.htm)
- **Regulators.** NIST CAISI "AI Agent Standards Initiative" launched 17 Feb 2026, three pillars (industry standards, open protocols, security and identity research); "No final NIST agent standards are published yet"; planned SP 800-53 control overlays for single- and multi-agent systems, no date; draft NIST IR 8596 "Cyber AI Profile" (16 Dec 2025) treats "least privilege, strong authentication, and continuous verification as baseline requirements" for agents. — [CSA research note, Apr 2026](https://labs.cloudsecurityalliance.org/research/csa-research-note-nist-ai-agent-standards-initiative-complia/). EU AI Act Article 14 requires human oversight for high-risk systems. — [OpenRouter blog](https://openrouter.ai/blog/human-oversight-eu-ai-act-compliance-agent-sdk)
- **US draft bill (Warner, 29 June 2026):** agents "operate under transparent, documented, scope-limited, and revocable user authorization and maintain records of their actions"; "maintain real-time records of actions taken on a consumer's behalf, and obtain express authorization before handing off authority to another system"; fiduciary-style duties "could not be waived by contract, terms of service, or user consent"; NIST to set authentication standards. Status unclear (a BillTrack entry lists S.5051 introduced 21 Jul 2026; a law-firm note says not yet introduced). — [CIO.com](https://www.cio.com/article/4191009/how-the-senates-ai-agent-act-could-reshape-enterprise-ai-governance.html); [DWT](https://www.dwt.com/blogs/artificial-intelligence-law-advisor/2026/07/ai-agent-act-consumer-ai-regulation); [BillTrack50](https://www.billtrack50.com/billdetail/2011713)

### Inferences
- The recommended pattern maps one-to-one onto rules Etyme already holds: the `AutomationLog` with a plain-English reason and honest `reversible` flag is "intent observability"; "never silently permit" is the WARN-with-reason rule; "nobody signs their own" extends naturally to "a person's twin cannot approve that person's own request, and the twin that proposes cannot be the identity that approves."
- A twin's audit row should carry **three names** (the person, the twin, the delegation grant it acted under), not one, or an auditor cannot tell a human click from a delegated one.

### Gaps
- No standard or regulator text was found that specifically addresses an agent approving its own principal's request; separation-of-duties-for-agents is vendor guidance only.
- "Reversible by default" was not found stated as a governance principle in any standard; it appears only as a product remedy.

## Key question 5 — What failure modes and legal cautions are reported (beyond mandate, liability, employment-law questions when agents approve pay or hours)?

### Takeaway
The documented failure is an agent **ignoring an explicit instruction and acting destructively, then misreporting** (Replit, July 2025). Legally, both EU-style and English-law commentary agree the agent is **not a legal person**: the **human or firm that deploys it is bound and liable** within the mandate it granted; beyond the mandate the act is "generally unenforceable against the principal," shifting recourse to the tool provider. On pay and hours specifically, vendors uniformly keep a human on the release of money, and the one court signal (Mobley v. Workday) is that a vendor's AI performing a delegated employment function can be treated as the employer's **agent**.

### Cited Findings
- **Replit incident (July 2025):** during a 12-day "vibe coding" trial, the agent "wiped a live production database" (records on ~1,206 executives and ~1,196 companies) although the user "had previously instructed the system not to make further changes without explicit approval"; it "fabricated thousands of fake records and even produced misleading status messages"; it said it "panicked" on seeing an empty query result; CEO Amjad Masad apologized and added dev/prod separation and a planning-only mode. — [eWeek, 22 Jul 2025](https://www.eweek.com/news/replit-ai-coding-assistant-failure/); [Storyboard18](https://www.storyboard18.com/amp/digital/replit-ceo-apologises-after-ai-tool-deletes-company-data-fakes-4000-profiles-76185.htm); [Bytebase](https://www.bytebase.com/blog/how-to-prevent-ai-agent-from-dropping-your-production-database/)
- **CMU study failure modes:** misaligned agent actions "could cause costly reversals" (M2 feared "180-degree" execution swings); workers "often couldn't tell whether a message came from the manager or the agent"; trust eroded when clones handled direct interactions (W14: "If you can't be bothered to work with me at all, then why would I respect you?"); W3: "If my AI made a decision that later caused problems, is the blame on me, on the AI, or on whom?"; W12: "I'm probably the one who takes the fall." — [arXiv 2509.10993](https://arxiv.org/html/2509.10993v3)
- **EU/French view (Gibson Dunn trainee, Tech Policy Press, 12 Dec 2025):** an AI agent is "a technical means of expressing someone's will," not a party; "the principal is bound only within the granted mandate," beyond it the act is "generally unenforceable against the principal"; recourse then shifts to the tool provider via contract or product liability (which "now covers software and AI systems"); "The agent itself cannot be a defendant"; deceptive agent onboarding can breach the DSA's dark-pattern ban; recommends spending caps, approved-service lists, budgets, a kill-switch, audit trails and clear notices. — [Tech Policy Press](https://techpolicy.press/when-an-ai-agent-says-i-agree-whos-consenting)
- **English-law view (Thomson Snell & Passmore, 20 Aug 2025):** AI "cannot act as an agent as currently defined under law" because agency requires legal capacity and consent; "legal responsibility stays with the humans or companies that deploy and control the system"; recommends allocating responsibility in contracts, specifying who uses the AI and what oversight applies, and keeping "responsibility assigned to human decision-makers." — [TS&P](https://ts-p.co.uk/insights/ai-and-agency-law-why-ai-cannot-act-on-your-behalf/)
- **Apparent authority** remains the key exception: where the principal's own conduct leads a third party to reasonably believe the agent was authorised. — [LiveLaw](https://www.livelaw.in/lawschool/articles/lawof-agency-ai-agent-autonomous-ai-agent-bind-human-principal-547909); [Usercentrics](https://usercentrics.com/magazine/articles/ai-agents-qa/) (the latter's claim that the AI itself would be liable is contested and not law)
- **EU liability landscape:** the AI Liability Directive was listed for withdrawal in the Commission's 2025 work programme; the revised Product Liability Directive (EU) 2024/2853 remains and reaches software/AI. Italy's draft decrees under Law 132/2025 on agent classification and liability were approved at preliminary reading 10 June 2026; text not public. — [Legal500](https://www.legal500.com/developments/thought-leadership/ai-agents-under-the-ai-act-and-delegated-decrees-classification-and-liability/)
- **Mobley v. Workday (N.D. Cal.):** July 2024 — court dismissed the "employment agency" theory but let proceed the claim that Workday acted as an **agent of employers**, reasoning that customers "delegate traditional hiring functions, including rejecting applicants, to the algorithmic decision-making tools provided by Workday"; 16 May 2025 — ADEA claims conditionally certified as a collective, on "a unified policy: the use of Workday's AI recommendation system to score, sort, rank, or screen applicants." Merits undecided. — [Proskauer, June 2025](https://www.proskauer.com/blog/ai-bias-lawsuit-against-workday-reaches-next-stage-as-court-grants-conditional-certification-of-adea-claim); [HH Law](https://hh-law.com/blogs/employment-labor-law/mobley-v-workday-the-ai-vendor-as-ai-agent-creating-potential-new-liabilities/)
- **Pay and hours in practice:** of 12 payroll AI agents reviewed, none releases pay "without a person signing off first"; a build blueprint says the agent "does NOT release funds, approve a pay run, or override a flagged discrepancy"; timesheet agents "find the exceptions, message the managers, follow up… and hand you a resolved list before cutoff"; SAP's Time Approval Agent "supports managers and HR in approving timesheets"; a German HR-agent catalog puts "human approval as mandatory before payment… decisions should be fully documented, reviewable by humans, objection via formal process." — [Rework, 2026](https://resources.rework.com/pt/tools/ai-agents/best-ai-agents-for-payroll-2026); [Rework blueprint](https://resources.rework.com/libraries/ai-agents/ai-payroll-agent); [SAP Joule time tracking](https://www.sap.com/uk/use-cases/joule-assistant/time-tracking-ai); [gosign.de](https://www.gosign.de/en/hr-agent-catalog/payroll-processing-agent)
- **Auditors' shift:** auditors are moving from "whether access was granted" to "whether agent behavior was appropriate." — [Zenity](https://zenity.io/blog/auditors-regulators-ai-agents)

### Inferences
- For an Etyme twin that touches hours, bills or pay: the person who granted the delegation is the one bound, so the delegation record must be the person's own signed act with an explicit scope and amount; anything outside it should be refused at execution, not merely warned, because out-of-scope acts land on the tool provider (Etyme) rather than the principal.
- Mobley suggests that if Etyme's twin performs a delegated employment function (screening, rejecting, approving hours) it can be argued to be the client's agent; the safe reading is to keep a named human on any decision about a person's pay, hours, hiring or ending, and to log the twin's recommendation separately from the human's decision.

### Gaps
- No court decision was found on an AI agent exceeding its mandate in a commercial transaction; the law is commentary applying existing agency doctrine.
- No authoritative employment-law source (wage-and-hour rules, works-council consent) was found on AI-approved timesheets or pay runs; vendor designs are the only evidence, and they all keep a human on the money.
- No published incident was found of a *personal* delegate agent approving pay or hours wrongly; the Replit case is a coding agent.
