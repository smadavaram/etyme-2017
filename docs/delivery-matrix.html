Etyme · delivery reference

Contingent delivery matrix

Seven value streams decomposed to the level a person or an agent actually picks up work. L1 is the stream, L2 the process group, L3 the process that has an owner and a service level, L4 the task.

Accounts payable, accounts receivable, credit and risk sit at L3 with everything else — they are processes with owners, not departments.

The question: are all the L2s part of onboarding?

Neither. Onboarding is an L3, and it happens five separate times — once per party, under two different L2s.

Treating it as one L2 is the classic mistake, and it is expensive because org charts follow taxonomies. Make onboarding an L2 and somebody creates an onboarding team; that team then owns five unrelated queues with different documents, different owners and different service levels, and it becomes the bottleneck every other stream waits on.

Client onboarding is a sales handover. Supplier onboarding is a due diligence exercise. Consultant onboarding is an employment formality. Assignment onboarding is a site badge and a laptop. Tenant onboarding is a software setup. One word, five processes, nothing shared but the word.

The contingent contract lifecycle

Eighteen stages. The four in clay are gates — a stage that can stop the deal rather than merely record it.

Who builds each of these

Six specialists own disjoint parts of the codebase and work at the same time; two more read only. Parallelism is bought with a boundary, not with coordination — every file has exactly one owner, checked by a test rather than described on a page.

The schema belongs to nobody. Every domain wants a column in the same file, and it is the one artefact where two individually correct changes still produce a wrong result, so it queues through etyme-architect. That is the single queue in an otherwise parallel system, and it is the cost of the arrangement.

Each L2 group below carries its owning agent. Work moves scout → schema → spec as test names → build → release → preview URL.
