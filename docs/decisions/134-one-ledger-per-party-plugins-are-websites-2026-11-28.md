# 134. One ledger per party; every plugin is its own website — 2026-11-28

Relayed by Pax (architect).

- Each plugin (training, pods and the rest) is its own website: a micro-site
  with its own micro dashboard.
- The core product centres on the party's ledger. Every party — a user, a
  client company, a candidate, a partner, an end client, a client at any
  layer — has one ledger covering:
  - activity: jobs, applications, timesheets, pod work, training,
    completions;
  - money: invoices, payments, rates, margins, fees, commissions;
  - documents: contracts, compliance papers, certificates.
- The core reaches a plugin only through an icon or a link. It never embeds
  a plugin's workflow or panel.
- Everything done inside a plugin writes back to the party's ledger, so the
  core picture stays complete. One ledger per party, never a second record.
- One login works everywhere: one sign-on and one session cover the core
  and every plugin website. No plugin accounts, no second login at any door.
  The separation is front-end only; at the back end the plugins talk to each
  other through the one ledger.
- Each reader sees the party's ledger through the rules that already stand:
  rates closed at every rung, a sub-vendor's name the prime's to keep, a
  client never sees a supplier's margin, before her yes a firm reads only
  what it typed, sensitive numbers masked.

## Pax's answers, 2026-11-28

- A supplier's seat confined to one team still reads all of that
  supplier's own contract lines, because nothing links a supplier's
  contract lines to its teams. Accepted for now; no narrowing rule is
  guessed. Open item.
- The Ledger tab lives on the person and company record pages. It is not
  added to the people list page or the worker's own page without a
  separate decision.
- Project teams and proposals move to their own plugin sites, as training
  did; the core keeps doors only.
